## Open questions raised during implementation

1. **Unsent changes on logout** — `@resgrid/offline` keeps them encrypted and owner-scoped (never sent for another user, dropped after 7 days); plan §8.9 says logout leaves no records. Keep or discard on logout?
2. **Legacy `http://` server URLs** — R/I/B builds may have stored an http URL; Omni ignores it (default server, user signs in again). Accept, or add a migration prompt?
3. **Status destination helpers** — strict by default, `{ lenient: true }` reproduces Unit. Which default?
4. **Core work needed** — register the five OAuth client ids as OpenIddict applications; honour idempotency keys on SaveCall/notes/messages; emit weather alert and checkInUpdated events; merge the `archived-calls` branch (`GetCallYears`, `GetArchivedCalls`, and add `SaveArchivedCall`) into `develop` for Dispatch's archived calls; send department setting 122 (`MappingNavigationConfig`: voice off by default, distance units, arrival radius, On Scene prompt, default avoid options) to the apps — navigation uses the documented defaults until then; deploy the MapLibre plan's Core work (committed on `develop` as f3b2fd24 + 34949e2d; not on the QA API on 2026-11-02) to QA, then refresh the Swagger snapshot and empty `packages/api/contract/swagger-v4-pending.json`; add `EstimatedDistanceMeters`/`EstimatedDurationSeconds` to `Routes/GetRoutePlansForUnit` (as `GetRoutePlans` has them); expose setting 122 to the apps (e.g. on `GetConfig` or `Routing/GetCapabilities`).
5. ~~**Legacy MMKV encryption keys in production**~~ — decided 2026-11-01 (plan D8): every native MMKV instance uses a device key generated into SecureStore; there is no key secret. Responder carries its files over (`storage.carryOver`: main instance re-encrypted once from its fixed key, offline queue adopts its existing device key; Omni does not yet import that legacy queue's items). Unit, IC, Dispatch and BigBoard delete their legacy files and users sign in again. Still to prove on devices in spike S4.
